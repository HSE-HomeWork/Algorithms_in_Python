# Объяснение решения

Вкратце на каждом рекурсивном шаге случайно выбирается опорный элемент `pivot`.
Массив разбивается на три группы:

- `left` — элементы больше `pivot`; т.к мы считаем по убыванию
- `right` — элементы меньше `pivot`;
- `count_pivot` — количество элементов, равных `pivot`.

Сначала рассматривается `left`, поскольку в нём находятся элементы, стоящие выше `pivot` в порядке убывания.

Если `k` не превышает размер `left`, искомый элемент находится в этой группе, и рекурсия продолжается с тем же `k`.

Если `k` попадает в диапазон позиций, занятых элементами, равными `pivot`, возвращается сам `pivot`.

Иначе поиск продолжается в `right`. Из `k` вычитаются размеры `left` и группы равных элементов:

## Оценка сложности

`n` — количество элементов во входном списке.

### Время

Ожидаемая сложность: **O(n)**.
Худшая сложность: **O(n²)**.

### Память

**O(n) в среднем**, **O(n²) в худшем случае**.

В этой реализации на каждом шаге создаются новые списки `left` и `right`.
Пока выполняется рекурсивный вызов, списки родительского вызова остаются в памяти.

## Визуализация

flowchart TD
    A["Вход: [7, 2, 9, 4, 9, 1, 6] k = 3"] --> B["pivot = 4"]
    B --> C["left (> 4): [7, 9, 9, 6]; count_pivot = 1; right (< 4): [2, 1]"]
    C --> D{"k не больше len(left)?"}
    D -->|"Да: 3 ≤ 4"| E["Рекурсия в left [7, 9, 9, 6], k = 3"]
    E --> F["pivot = 7"]
    F --> G["left (> 7): [9, 9] count_pivot = 1 right (< 7): [6]"]
    G --> H{"k не больше len(left)?"}
    H -->|"Нет: 3 > 2"| I{"k не больше len(left) + count_pivot?"}
    I -->|"Да: 3 ≤ 3"| J["Возвращаем pivot = 7"]
    J --> K["Результат: 3-й по величине элемент — 7"]
